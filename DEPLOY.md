# Deploying Modern Monkey

Three pieces, three hosts:

| Piece            | Host    | Cost        |
| ---------------- | ------- | ----------- |
| React storefront | Netlify | free        |
| Express API      | Render  | free        |
| PostgreSQL       | Neon    | free        |

The browser only ever talks to the Netlify domain — `netlify.toml` proxies
`/api/*` to Render, so there is no CORS setup and the refresh-token cookie
stays first-party.

---

## 1. Database — Neon

1. Create a project at <https://neon.tech> (region close to your Render region).
2. Copy the **pooled** connection string from *Dashboard → Connection Details*
   (host contains `-pooler`), e.g.
   `postgresql://user:pass@ep-xxx-pooler.us-east-1.aws.neon.tech/neondb?sslmode=require`
3. Load the schema from your machine (needs the repo checked out):

   ```bash
   cd server
   npm install
   DATABASE_URL="postgresql://...pooler...?sslmode=require" npm run db:setup
   ```

   `db:setup` is idempotent — re-running it never drops data.

---

## 2. API — Render

### Create the service

1. <https://dashboard.render.com> → **New → Blueprint**, pick this repo. Render
   reads [`render.yaml`](render.yaml) and creates `modern-monkey-sale-api`.
   (Or **New → Web Service** manually: root directory `server`, build
   `npm install`, start `npm start`, health check path `/api/health`.)
2. Set the env vars marked "you fill this in":

   | Key             | Value                                                       |
   | --------------- | ---------------------------------------------------------- |
   | `DATABASE_URL`  | the Neon pooled string from step 1                         |
   | `CLIENT_ORIGIN` | your Netlify URL, e.g. `https://modern-monkey-sale.netlify.app` |
   | `APP_URL`       | same Netlify URL (used in password-reset emails)          |

   `JWT_SECRET` is generated by Render. `NODE_ENV=production` is already set
   (required — it makes the auth cookie `Secure`).
3. Deploy. When it is live, check `https://<your-app>.onrender.com/api/health`
   returns `{"status":"ok",...}`.
4. Create the first admin (Render dashboard → your service → **Shell**):

   ```bash
   ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='a-strong-password' npm run create-admin
   ```
5. *(optional)* Load the 60-product demo catalogue:

   ```bash
   npm run seed:catalog
   ```

> Render's free tier sleeps after ~15 min idle; the next request cold-starts in
> ~50s. The local disk is ephemeral, so **admin image uploads won't survive a
> restart** — for persistent uploads set `STORAGE_PROVIDER=s3` and the
> `STORAGE_*` vars (Cloudflare R2, AWS S3, or any S3-compatible store). Browsing
> the seeded catalogue needs none of this.

---

## 3. Storefront — Netlify

1. Edit [`netlify.toml`](netlify.toml) — replace
   `REPLACE-WITH-RENDER-APP.onrender.com` with your real Render host. Commit and
   push.
2. <https://app.netlify.com> → **Add new site → Import an existing project**,
   pick this repo. Netlify reads `netlify.toml`: base `client`, build
   `npm run build`, publish `client/dist`. No env vars needed.
3. Deploy. Open the site, confirm products load, then sign in with the admin
   account from step 2.4.
4. If you set a custom domain later, update `CLIENT_ORIGIN` and `APP_URL` on
   Render to match.

---

## Redeploys

Both hosts auto-deploy on push to `main`:

- push touching `client/**` → Netlify rebuilds
- push touching `server/**` → Render rebuilds

## Local development is unchanged

`server/.env` with the discrete `PG*` vars still works — `DATABASE_URL` only
takes over when it is present. The Vite dev proxy still points at
`http://localhost:5000`.
